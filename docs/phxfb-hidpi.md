# PhxAMDFB HiRes metadata for the existing GOP output

`PhxAMDFB` exposes the active firmware (GOP) scan-out as one physical mode. Its `getInformationForDisplayMode` advertises `kDisplayModeValidForHiResFlag` for that existing mode by default, regardless of the **internal panel's** PCI device ID, product ID, EDID, brand, or fixed resolution. Here “general” means reusable for differing panels under the currently supported GOP-backed display path, **not** multi-display or external-connector support. `-phxhidpioff` is a diagnostic boot-argument opt-out; it leaves Valid/Safe/Default-only mode flags in this branch without changing firmware timing. The read-only registry property `PhxFBHiResModeFlag` reports whether this flag was enabled at start.

This is a **mode capability hint**, not a forced mode switch or a guarantee that CoreDisplay will generate a selectable 2× mode for every internal panel. The OS still decides which logical modes are usable. `connectFlags` continues to provide only Valid/Safe/Default connection-sensing bits; `kIOConnectionBuiltIn` remains a distinct connection attribute. No per-machine EDID is embedded, no DDC capability is claimed, and no additional physical timing, clock or pixel buffer size is created. The existing display-pipe copy still requires a source the same size as the scan-out; larger-than-native backing needs separate scaling support. The driver does **not** enumerate, train or drive a second HDMI/Type-C DisplayPort output; this HiRes change adds no such functionality. Upstream lists external display PHY support as work in progress, outside this patch's scope.

On the ThinkBook 14+ 780M with a 3072×1920 GOP raster, an earlier machine-gated build adding **the same HiRes mode flag** produced a public, usable 1536×960 logical mode with 3072×1920 pixels and `NSScreen.backingScaleFactor=2`; see [`thinkbook-hidpi-validation.md`](thinkbook-hidpi-validation.md). That is evidence for this flag on **one** device, not a test of this generalized binary on other hardware. The same test retained `IOFBtv=Yes`/Television mode flags and used the pre-existing user display override to supply EDID. Do not infer that EDID injection, built-in mode flags or physical timing changes are universally needed.

## Validation before deploying elsewhere

1. Build with the pinned MacKernelSDK and verify the x86_64 kext, upstream bundle version, and ad-hoc signature. The change is scoped to `phxfb.cpp`; do not reuse an old machine-specific binary or assume its SHA identifies this build.
2. On a separately consented target, preserve the currently installed kext and AuxKC with checksums and confirm that an AuxKC rebuilt with this binary retains every unrelated extension. Never replace the working setup solely because an offline build succeeds.
3. After a user-controlled reboot, independently check the public mode list and *current* logical width/height, pixel backing, NSScreen scale, native scan-out dimensions and refresh, and display-transaction failures. A private candidate alone is not acceptance. If a 2× mode appears but rendering fails, investigate the particular transaction/API; do not inject arbitrary modes or scaled physical timings.
4. Compare supported **internal** GPU/panel configurations separately. A result on one ThinkBook does not validate other internal panels, 760M/740M, 120 Hz or larger-than-native backing. If a configuration fails, use the opt-out or restore the verified original kext before investigating its distinct cause. External connectors are not a target or validation requirement for this patch.

The deployed ThinkBook test candidate is an immutable earlier artifact built from commit `1a3623c`; this generalized source commit is **not deployed** to that machine. The bundle version in this branch follows upstream rather than the older local test candidate. No installation or reboot is part of this source change.
